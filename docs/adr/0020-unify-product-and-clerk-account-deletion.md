# Unify product and Clerk account deletion

Treat an authenticated product deletion request and a verified Clerk `user.deleted` webhook as idempotent entry points to one terminal Personal Account Deletion state machine. It first marks the account deleting and revokes all MCP token families, API Keys, and data-plane access, clearing every API Key digest before tenant access or key use can continue, then cancels Connection Setups and starts Connection Deletion for every retained connection; an in-product request deletes the Clerk identity only after this local intent is durable. Within 24 hours, all User-addressable tenant data and ordinary Activity Logs are purged, and remaining API Key rows cascade with the Personal Account. Only security-relevant auth/tool events may first be transformed into records with no User, account, connection, authorization, API Key, network, message, contact, or provider reference; those retain category, allowlisted client class, outcome, counts, timing, and latency only until each source event's original 90-day expiry. Provider-cleanup audit keyed only to the deletion marker expires 90 days after completion, while content-free locked deletion markers remain as restore guards. Active data and backup remnants otherwise follow the existing 24-hour and 30-day deletion guarantees. This prevents a deleted identity from leaving an accessible orphan tenant and makes later signup a new account rather than recovery.

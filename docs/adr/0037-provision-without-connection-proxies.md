# Provision WhatsApp Connections without per-Connection proxies

The production provider-control composition provisions new Wasender sessions without a `proxy_url`. This supersedes ADR 0004 and ADR 0019 only where those decisions require Webshare, a Colombian static ISP proxy, and serialized proxy-pool allocation. Webshare is not a startup dependency, its API key and allocation Durable Object are not bound to provider-control, and missing proxy inventory cannot block Connection Setup. Provider message logging and automatic incoming-message reads remain disabled, provider-control remains private, and all other Wasender lifecycle reconciliation rules remain unchanged.

The dormant Webshare selector and the already-migrated Durable Object class remain in source so retained deployment history is not destroyed. Re-enabling proxies requires a new reviewed decision, a statically composed production dependency, restored manifest and infrastructure bindings, and end-to-end provisioning evidence. This is not a runtime flag. Existing provider sessions are not rewritten merely to remove a previously assigned proxy; Connection Setup and later reconciliation stop requiring one.

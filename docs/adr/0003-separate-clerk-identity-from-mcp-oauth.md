# Separate Clerk identity from MCP OAuth

Use Clerk as the human identity provider and the Cloudflare API Worker as the OAuth authorization server and MCP resource server. The Worker uses Clerk authentication during authorization, then issues and validates its own resource-bound MCP tokens and enforces connection grants plus `connections:read`, `directory:read`, `messages:read`, and `messages:send` scopes. `list_connections` requires connection read; contact and group lists require Directory read; conversation lists, message reads, and Stored Media resources require message read; text and PDF sends and same-authorization send status require send. Every handler also checks the selected connection. Send permission never implies Directory or message-read permission, so a send-only caller can use a previously known recipient handle but cannot discover recipients or content. Consent renders in the Vercel app, requires Clerk reverification within five minutes, names an allowlisted MCP Client, requires separate unselected-by-default read-sharing and send-authority confirmations, and records an explicit set of WhatsApp Connections. ChatGPT and Claude may identify an MCP Client with a reviewed Client ID Metadata Document. The API admits ChatGPT only when Cloudflare's SSRF-protected fetch validates a `chatgpt.com` document with the reviewed path shape and every redirect stays on `chatgpt.com`. It admits Claude only through the exact `https://claude.ai/oauth/mcp-oauth-client-metadata` document and exact `https://claude.ai/api/mcp/auth_callback` redirect. Deployment automation uses the separate source-allowlisted `deployment-smoke` public PKCE client, requests only `connections:read`, and redirects only to the registered `http://127.0.0.1/oauth/callback` loopback path; RFC 8252 ephemeral ports are accepted while the scheme, IP literal, path, query, and fragment remain fixed. Dynamic client registration remains disabled, so OAuth KV cannot expand the reviewed client policy.

ChatGPT metadata that selects `none` or `private_key_jwt` is admitted as the same public PKCE client because the Cloudflare provider's CIMD token flow supports public clients only. Client metadata discovery is used only while admitting the authorization request; authorization-code and refresh exchanges use the validated, normalized public-client registry so the provider does not reinterpret `private_key_jwt` as a client-secret requirement. Claude metadata must select `none`; every other token endpoint authentication method fails closed. The Cloudflare OAuth library's required KV stores hashed or encrypted protocol artifacts, while Neon is authoritative for the MCP Authorization, scopes, selected connections, User/account status, and revocation. Every tool call, protected media resource read, and token refresh checks that current Neon state, so KV propagation does not extend application access after revocation. Access tokens expire after 10 minutes; one-time rotating refresh tokens expire after 30 days of inactivity and after a 90-day absolute authorization session, and refresh-token reuse revokes the token family. Send Operation retention is a 90-day storage and replay-protection maximum, not an access guarantee: replay and status require the originating MCP Authorization to remain active, and a later reauthorization does not gain access to an earlier authorization's operations. This preserves one User sign-in system while avoiding reliance on Clerk's currently undocumented custom-scope and exact MCP-resource audience behavior.

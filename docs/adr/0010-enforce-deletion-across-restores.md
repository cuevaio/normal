# Enforce connection deletion across active data and restores

Connection Deletion immediately revokes MCP access, removes the WhatsApp Connection from every API Key, permanently revokes a key that loses its last selected Connection and clears its credential digest, and makes connection keys unavailable. It then purges active Neon and R2 data within 24 hours, and allows encrypted remnants to age out of provider backups within at most 30 days. Ordinary disconnection does not remove API Key selection or revoke the key. The restore-external deletion authority is a dedicated private R2 bucket of idempotent Personal Account and connection markers under an indefinite bucket-lock rule. Marker keys use a dedicated HMAC over environment, entity type, and opaque identifier, and marker bodies contain only version, deletion kind, and timestamps; they contain no identity, phone, provider identifier, content, or credential. After a marker is durable but before tenant key envelopes are removed, a privileged transaction copies only the required provider account/session identifiers into a separate R2 Deletion Capsule encrypted under the deletion-coordinator KMS key and bound to that marker. The coordinator can decrypt capsules but no tenant content, asks provider-control to delete and reconcile the session, destroys the capsule after confirmed absence, and pages on cleanup risk before the 24-hour deadline. The coordinator can create and read markers but cannot alter lock policy, and infrastructure access is separated and audited. Marker replay and re-purge complete before traffic is served after any Neon restore, so restored rows and key envelopes cannot resurrect deleted data. Connection marker replay destroys only the selected WhatsApp Connection key and preserves the Personal Account key; Personal Account marker replay destroys the account key. If Connection replay removes the row before current provider cleanup completes, an opaque Deletion Continuation retains the marker-to-Setup relationship so the deletion coordinator keeps the WhatsApp Number reserved until provider absence and then removes the Setup atomically. Once replay reaches a terminal ready or verified state for the same branch, later scheduled coordinator runs return no candidates so ordinary serving-branch deletions stay on the live deletion path. Provider-session deletion is retried and audited; general availability depends on Wasender supplying a written deletion and backup-erasure SLA compatible with this promise.

# Set measurable private-beta recovery objectives

Offer no contractual availability SLA during the private beta, but operate the first-party product and data plane to a 99.5% monthly availability SLO, a four-hour recovery-time objective, and a five-minute recovery-point objective for committed Neon state recoverable through Neon's managed backup and PITR path. Configure and verify a seven-day Neon history window; do not build custom `pg_dump`, logical-replication, or cross-provider database backups for the beta, accepting that the five-minute objective does not cover catastrophic loss of the Neon account or service. Time-based retention promises, including the seven-day Pending Send Content maximum, describe active application readability; encrypted remnants may remain in managed PITR history until that seven-day history ages out. Every restore must replay deletion markers, globally revoke restored API Keys and clear their credential digests, rotate `API_KEY_HMAC_SECRET` to a newly generated value whose predecessor is not accepted as a verification fallback, and apply current wall-clock expiry to Pending Send Content, Send Operations and idempotency bindings, Activity Logs, Stored Messages, and Stored Media before verification access or serving traffic, so older restored state never reopens expired data or a restored grant. Stored Media likewise has no backup RPO: R2 is its sole retained copy, so loss or accidental removal of the primary object can be permanent and must surface as `failed` rather than as available media. These choices deliberately accept correlated provider and logical-deletion risk. Measure Wasender and WhatsApp dependency availability separately rather than excluding first-party failures or implying an end-to-end guarantee the provider does not make. Provider events never delivered to the platform are outside storage RPO and produce disclosed Ingestion Gaps when detected; immutable deletion markers have a zero-data-loss objective and must be replayable before a restore serves traffic.

Every month, automatically restore a randomly selected point from the prior history window into a non-serving branch, replay deletion markers, revoke restored API Keys, clear their digests, reject the predecessor API Key HMAC, apply wall-clock expiry before verification access, and test schema compatibility, RLS isolation, sampled key use, data invariants, quota/audit integrity, and continued absence of deleted or expired identifiers and readable content while recording achieved RPO and RTO. Every quarter, run a timed game day that also rotates endpoints, reconstructs OAuth KV, exercises Queue replay fixtures, validates KMS and R2 access, and proves traffic cannot bypass the deletion and expiry gates. A successful full drill is a general-availability prerequisite.

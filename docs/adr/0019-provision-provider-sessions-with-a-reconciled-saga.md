# Provision provider sessions with a reconciled saga

Create or return a durable Connection Setup from a browser-generated idempotency key and persist its provisioning intent before calling Wasender. The Setup reserves a dedicated platform-wide HMAC token for the normalized WhatsApp Number, distinct from connection-scoped lookup indexes, and its opaque identifier becomes the deterministic provider session name. A leased queue consumer asks the provider-control Worker to reconcile that marker before every attempt: adopt exactly one existing session, create only when none exists, and quarantine duplicates rather than blindly repeating an ambiguous create. The provisioning queue has a platform-wide maximum concurrency of one, and provider-control routes every create, proxy-aware reconciliation, repair, and reconnect validation through the one Durable Object representing that environment's provider proxy pool. This shared gate prevents setup and scheduled repair read-then-write allocation races. A proxy-changing write reserves the pool with an opaque setup marker and settlement deadline; an ambiguous result keeps later allocations blocked until an alarm or caller reconciliation safely settles it. This coordination state contains no proxy assignment or credential and does not become an assignment authority. Provider identifiers and encrypted per-session credentials are persisted before setup advances, while cancellation or expiry drives audited provider cleanup. The number remains reserved for a disconnected connection and throughout deletion or expired-setup cleanup, and is released only after provider-session removal is confirmed. This contains Wasender's lack of documented creation idempotency without placing the account-level PAT outside provider-control.

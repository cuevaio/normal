# Use authorization-bound keyset cursors

Return all `list_connections` results unpaginated, but paginate contacts, groups, conversations, and Stored Messages with a default of 20 and maximum of 50 using deterministic keyset order. A short-lived HMAC cursor binds the MCP Authorization, tool, explicit connection handle, normalized filters or search, limit, sort version, last sort tuple, and expiry; any mismatch is an `invalid_cursor` execution error. REST Directory contacts, groups, WhatsApp Conversations, Stored Message pages, and private Stored Message search use a separate signing document that binds the API Key grant, stable operation ID, Connection, normalized filters or a keyed digest of normalized search terms, limit, sort version, boundary, and expiry; MCP and REST cursors are not interchangeable, and search terms themselves never appear in a cursor. Directory entries sort by normalized display name and handle, conversations sort by Conversation Activity descending and handle, and Stored Messages select the newest page first then return records chronologically with an older-traversal cursor on `sent_at` and message handle. Search results remain newest-first by `sent_at DESC, message_id DESC` and stay capped at 20. Responses include `next_cursor`, `has_more`, and projection freshness, Message History Window, or search-coverage metadata. Traversal is intentionally not a persisted snapshot, so concurrent changes may move entries and clients can restart from the first page.

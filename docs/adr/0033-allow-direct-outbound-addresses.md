# Allow direct outbound addresses

Allow REST and MCP text Send Operations to select exactly one destination: an existing `ctc_` or `grp_` WhatsApp Recipient handle, an E.164 `phone`, or a Normal-constrained WhatsApp `username` matching `^@[A-Za-z0-9._-]{1,64}$`. Phone and username inputs are Direct Addresses and need not exist in the WhatsApp Directory. This supersedes only ADR 0006's handle-only destination and Directory-eligibility restriction; all authorization, Client Confirmation, idempotency, quota, durable attempt, ambiguous-outcome, and no-retry rules remain unchanged.

A Direct Address remains in request memory only through the one provider attempt. Neon stores its non-sensitive destination kind and the existing non-reversible request fingerprint, but not the phone number or username; receipts, Activity Logs, telemetry, errors, and Send Status never expose it. Existing handle fingerprints remain byte-for-byte compatible, while direct fingerprints use a purpose prefix so equal phone and username strings cannot collide. Pending Send Content is deleted as soon as the operation leaves `processing`, including lease expiry after a crashed attempt, because Direct Address evidence cannot safely materialize it. Identity-bearing provider evidence for a username alias is accepted only when the provider echoes the exact username. If the provider returns a resolved phone or LID JID, the causally bound response may establish `accepted` but cannot establish recipient identity or materialize Pending Send Content as a Stored Message. Later exact shared message identity may still advance Send Status, while an independently observed outbound upsert creates its Stored Message under the Directory identity it actually carries.

Direct Address aliases cannot be proven distinct from an excluded WhatsApp Recipient. A new Direct Address send therefore returns the existing constant-shape recipient-not-found result whenever any active WhatsApp Recipient Exclusion exists on the Connection. Activating an exclusion purges Pending Send Content for every unattributed Direct Address operation on that Connection, including operations committed while the exclusion transition was being prepared. Removing all exclusions permits future Direct Address sends but does not restore purged content. This conservative rule prevents phone or username addressing from bypassing recipient exclusions without persisting a new alias authority.

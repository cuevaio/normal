# Accept API Keys at the MCP endpoint

Allow `POST /mcp` to authenticate either an OAuth access token backed by an MCP Authorization or an existing `normal_apk_<handle>.<secret>` API Key. Route only API Key-shaped bearer credentials through the purpose-specific HMAC and authoritative Neon bootstrap before OAuth middleware, and never fall back to OAuth after API Key authentication fails. Keep the resulting authority as a protocol-neutral union of distinct MCP Authorization and API Key grants: permissions map directly to MCP capabilities, selected Connections and lifecycle state are rechecked, MCP cursors bind API Keys as `api:<grant-id>`, Send Operations retain the API Key grant across REST and MCP, and Activity Logs record the MCP channel independently from the API Key principal. Do not accept credentials through URLs, query parameters, JSON-RPC `_meta`, `x-mcp-header`, or any header other than `Authorization: Bearer`.
